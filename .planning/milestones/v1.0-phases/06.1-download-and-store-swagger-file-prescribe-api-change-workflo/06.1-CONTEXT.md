# Phase 6.1 Context: API Spec Sync Workflow

## Scope

Download and store the TwentyThree OpenAPI/Swagger spec in the repository. Provide a repeatable update workflow: download the latest spec, diff it against the stored version, and surface the changes as input for Claude to apply necessary code changes. Document the workflow in CLAUDE.md so Claude agents running in this project know what to do when the API changes.

---

## Decisions

### D-1: Swagger file location — `specs/twentythree-api-swagger.json`

Store the spec in a `specs/` directory at the **CLI package root** (`packages/twentythree-cli/specs/twentythree-api-swagger.json`).

**Rationale:** Keeps API artifacts near the CLI package that consumes them, distinct from generated output (`src/api/types.ts`). The `specs/` name signals "source of truth inputs" vs. `src/api/` which holds generated output.

**Effect on `generate-types`:** Update the root `generate-types` script to point at the local file instead of the live URL:
```
openapi-typescript packages/twentythree-cli/specs/twentythree-api-swagger.json -o packages/twentythree-cli/src/api/types.ts
```
The live URL fetch moves to the update script (D-3).

### D-2: Change visibility — raw diff, Claude-ready input

When a new spec is downloaded, the change output is a raw `git diff` of `specs/twentythree-api-swagger.json`. No semantic parsing or human-readable summary layer.

**Rationale:** The diff serves as direct input for Claude and task prompts. A semantic summary layer would add complexity without adding value — Claude reads JSON diffs natively.

**Output format:** The update script prints the diff to stdout. The developer pipes it or pastes it into a Claude Code session per the CLAUDE.md workflow (D-4).

### D-3: Update workflow — shell script at CLI package root

A shell script at `packages/twentythree-cli/update-api-spec.sh`:
1. Downloads the latest spec from `https://video.twentythree.com/apidocs/swagger.json`
2. Writes it to `specs/twentythree-api-swagger.json`
3. Runs `git diff specs/twentythree-api-swagger.json` and prints the diff
4. Runs `pnpm generate-types` to regenerate `src/api/types.ts` from the new spec
5. Prints a summary: "Spec updated. Review the diff above, then follow CLAUDE.md § API Change Workflow."

The script is executable (`chmod +x`) and documented in the package README.

Also add a root-level npm/pnpm script alias: `"update-api-spec": "cd packages/twentythree-cli && ./update-api-spec.sh"` so it can be run from the monorepo root.

### D-4: Claude integration — CLAUDE.md section

Add a dedicated section to `CLAUDE.md` titled `## API Change Workflow` that documents what to do when the spec changes.

**Contents of the section:**
1. How to run the update script
2. What the diff output means
3. How to use Claude Code to apply the changes: paste the diff + TypeScript errors, ask Claude to update affected command files and fix broken types
4. Verification step: run `pnpm --filter twentythree-cli exec tsc --noEmit` and `pnpm --filter twentythree-cli test --run` to confirm nothing is broken
5. Commit instructions: commit both `specs/twentythree-api-swagger.json` and any changed command files together

**Placement:** Append to the existing `CLAUDE.md` in the repo root (not a new file). Section should be self-contained so Claude agents starting a fresh session immediately know the process.

## Established Patterns (from prior phases)

- **Type generation:** `openapi-typescript` CLI, outputs to `src/api/types.ts`
- **Current live URL:** `https://video.twentythree.com/apidocs/swagger.json`
- **Script runner:** `pnpm --filter twentythree-cli exec` for CLI package scripts
- **Root scripts:** Defined in root `package.json` `scripts` section

---

## Out of Scope

- Automated CI/CD polling for spec changes — this is a manual developer workflow
- Semantic diff parsing / change summarization — raw diff is sufficient
- A `twentythree api sync` CLI command — shell script is simpler and fits the developer-tool nature of the workflow
