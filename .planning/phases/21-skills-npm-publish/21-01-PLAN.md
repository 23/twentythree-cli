**2. Guard existing publish job (per D-03):** Add an `if:` line after `publish:` and before `runs-on:`:
```yaml
jobs:

    if: "!startsWith(github.ref, 'refs/tags/skills-v')"

```
The `if:` value MUST be quoted because `!` is a YAML special character.

**3. Add publish-skills job (per D-02, D-04, D-05, D-06):** Insert a new job between the `publish` job and the `smoke-test` job. The complete job definition:

```yaml
  publish-skills:
    if: startsWith(github.ref, 'refs/tags/skills-v')
    runs-on: ubuntu-latest
    permissions:
      id-token: write
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'pnpm'
          registry-url: 'https://registry.npmjs.org'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Validate skills package
        run: pnpm --filter twentythree-skills test --run

      - name: Dry-run publish (verify NPM_TOKEN scope)
        working-directory: packages/twentythree-skills
        run: npm publish --dry-run
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

      - name: Publish to npm
        working-directory: packages/twentythree-skills
        run: pnpm publish --no-git-checks --provenance
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

Key details:
- `permissions: id-token: write` is REQUIRED for `--provenance` (Sigstore OIDC token). The existing `publish` job has no permissions block — do NOT add one to it.
- `registry-url: 'https://registry.npmjs.org'` is REQUIRED for NODE_AUTH_TOKEN injection into .npmrc.
- Dry-run step uses `npm publish --dry-run` (not pnpm) per D-06.
- Real publish step uses `pnpm publish --no-git-checks --provenance` per D-05.
- The `smoke-test` job's `needs: publish` line stays unchanged — it only depends on the CLI publish job, not the skills job.

The final file should have 4 top-level keys under `jobs:`: `publish`, `publish-skills`, `smoke-test`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions -> npm registry | CI job publishes package using NPM_TOKEN secret; compromised token = unauthorized publish |
| Git tag push -> CI trigger | Anyone with push access can trigger a publish by creating a matching tag |
| npm registry -> end users | Published package is executed by `npx`; supply chain integrity matters |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | Spoofing | Git tag push | mitigate | Tag-guarded `if:` conditions ensure `skills-v*` only triggers skills publish, `v*` only triggers CLI publish — no cross-contamination |
| T-21-02 | Tampering | npm package content | mitigate | `pnpm publish --provenance` with `permissions: id-token: write` generates Sigstore attestation linking package to specific GitHub commit |
| T-21-03 | Information Disclosure | NPM_TOKEN in CI logs | mitigate | Token passed via `env: NODE_AUTH_TOKEN` which GitHub Actions masks in logs; never echoed in run commands |
| T-21-04 | Elevation of Privilege | NPM_TOKEN scope too broad | accept | Dry-run step (D-06) validates token has access before real publish; token scope is verified but controlled by npm account admin — if token is over-scoped, that is an account-level concern outside CI |
| T-21-05 | Denial of Service | Double-publish on tag push | mitigate | `if:` guards on both jobs (D-03/D-04) ensure exactly one job runs per tag push — no double-trigger possible |
</threat_model>
