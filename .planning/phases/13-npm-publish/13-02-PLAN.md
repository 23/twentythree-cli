  <action>
The developer must create an npm automation token and add it as a GitHub repository secret. This cannot be automated by Claude because it requires authenticated access to both npmjs.com and GitHub repository settings.

**Step 1: Create npm automation token**
1. Log into https://www.npmjs.com
2. Click your avatar → Access Tokens
3. Click "Generate New Token" → select "Classic Token"
4. Token type: **Automation** (this bypasses 2FA prompts in CI, which is required for non-interactive publishing)
5. Copy the generated token

**Step 2: Add as GitHub repository secret**
1. Go to https://github.com/23/twentythree-cli/settings/secrets/actions
2. Click "New repository secret"
3. Name: `NPM_TOKEN`
4. Value: paste the npm automation token from Step 1
5. Click "Add secret"

**Verification:** The secret should appear in the repository secrets list as `NPM_TOKEN` (value hidden).

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Create v1.0.0 tag and push to trigger CI publish</name>
  <read_first>
    - packages/twentythree-cli/package.json (confirm version is 1.0.0 from Plan 01)
    - .github/workflows/release.yml (confirm workflow exists from Plan 01)
  </read_first>
  <action>
Per D-04 and D-05, the developer creates and pushes the v1.0.0 tag to trigger the release workflow. Since the version was already bumped to 1.0.0 in Plan 01, we only need to create the tag and push.

**From the repository root**, run:
```bash
git tag v1.0.0
git push origin v1.0.0
```

This pushes the v1.0.0 tag which triggers `.github/workflows/release.yml` (per D-03 and D-05, trigger pattern is `tags: ['v*']`).

**Then monitor the GitHub Actions run:**
1. Go to https://github.com/23/twentythree-cli/actions
2. The "Release" workflow should appear as triggered by the `v1.0.0` tag push
3. Watch the `publish` job: it should run tests, build, and publish to npm
4. Watch the `smoke-test` job: it should install globally and verify `twentythree --version`
5. Both jobs should complete with green checkmarks

**If the publish job fails:**
- `ENEEDAUTH` → verify NPM_TOKEN secret is set and `registry-url` is present in workflow
- `ERR_PNPM_GIT_UNCLEAN` → verify `--no-git-checks` flag is in workflow
- Test failures → fix tests, delete the tag (`git tag -d v1.0.0 && git push origin :refs/tags/v1.0.0`), fix the issue, re-tag and push

**If the smoke-test job fails:**
- 404 on install → registry propagation may need more time; re-run the job
- `twentythree --version` fails → investigate the published package contents
  </action>
