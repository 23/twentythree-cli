Storage is the ONLY anomalous analytics command. Per RESEARCH.md:
- The API endpoint only accepts `fields` parameter -- no date params, no p/size
- The response `data` is a single object (not an array) -- Pitfall 6
- Per D-3, still expose `--date-start`/`--date-end`/`--date-expression` flags for consistency, but the API silently ignores them

**File: `analytics/usage/storage.ts`**
- Class: `AnalyticsUsageStorage extends AuthenticatedCommand<typeof AnalyticsUsageStorage>`
- `static description = 'Get storage usage analytics'`
- `static enableJsonFlag = true`
- `static flags = { ...AuthenticatedCommand.baseFlags, ...ANALYTICS_DATE_FLAGS, ...ANALYTICS_FILTER_FLAGS }` -- include date flags per D-3 for consistency, but do NOT include ANALYTICS_PAGINATION_FLAGS (no p/size per API spec)
- API path: `this.apiClient.GET('/analytics/data/usage/storage', { params: { query: { date_start: flags['date-start'], date_end: flags['date-end'], date_expression: flags['date-expression'], selection: flags.selection } } })`
- Response handling is DIFFERENT from other analytics commands because `data` is a single object, not an array:
```typescript
const resp = data as any
const storageData = resp?.data

if (this.jsonEnabled()) {
  return formatJsonOutput({
    ok: true,
    data: storageData ?? {},
    summary: 'Storage usage data',
    breadcrumbs: [
      { domain: this.activeWorkspace.domain },
      { resource: 'analytics' },
    ],
  })
}

if (!storageData || Object.keys(storageData).length === 0) {
  this.log('No storage data found.')
  return
}

// Render as key-value pairs (like video get) since data is a single object
for (const [key, value] of Object.entries(storageData)) {
  this.log(`${key}: ${value}`)
}
```
- Do NOT use `renderTable()` for storage -- it returns a single object, not an array (Pitfall 6)
- Do NOT use `Array.isArray` guard -- just render as key-value
