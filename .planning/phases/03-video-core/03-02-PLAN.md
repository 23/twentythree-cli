    - uploadChunkPool processes chunks in windows of `concurrency` size
    - When uploadFn returns 200, chunk is marked complete and onChunkComplete fires
    - When uploadFn returns 500, entire pool aborts with "Unsupported file format" error
    - When uploadFn returns other status (e.g. 502), retries up to maxRetries times
    - Retry uses exponential backoff: delay = min(1000 * 2^attempt, 30000) ms
    - If a chunk fails maxRetries times, pool aborts with "Chunk N failed after 5 retries"
    - Already-completed chunks (in completed Set) are skipped
    - onChunkComplete callback receives the chunk descriptor and response data
    - Final chunk response data (containing photo_id, tree_id, token) is captured and returned
  </behavior>

    ```typescript
    import { ChunkDescriptor } from './types.js'

    export interface ChunkUploadResponse {
      status: number
      data?: { photo_id?: number; tree_id?: number; token?: string }
    }

    export interface ChunkPoolParams {
      chunks: ChunkDescriptor[]
      uploadFn: (chunk: ChunkDescriptor) => Promise<ChunkUploadResponse>
      concurrency: number
      maxRetries: number
      onChunkComplete?: (chunk: ChunkDescriptor, response: ChunkUploadResponse) => void
    }

    export interface ChunkPoolResult {
      completedChunks: number
      finalResponse?: ChunkUploadResponse['data']
    }

    export async function uploadChunkPool(params: ChunkPoolParams): Promise<ChunkPoolResult>
    ```

    Implementation details:
    - Use a `Set<number>` to track completed chunk numbers within the invocation (UPL-06 in-memory resume)
    - Process chunks in windows: `for (i = 0; i < chunks.length; i += concurrency)`, then `Promise.all` on the window
    - Each chunk attempt: call `uploadFn(chunk)`, check status:
      - `200` → add to completed set, call `onChunkComplete`, capture response data
      - `500` → throw `new Error('Unsupported file format — upload aborted')`
      - Other → increment attempt counter, delay with exponential backoff, retry
    - After all retries exhausted → throw `new Error(\`Chunk ${chunk.number} failed after ${maxRetries} retries\`)`
    - Track the last successful response data (the final chunk's 200 response contains photo_id/tree_id/token)
    - Export a `delay(ms: number)` helper (or inline setTimeout promise) for backoff — make it injectable for testing

    Write tests in `__tests__/chunk-pool.test.ts`:

    - Mock `uploadFn` returning 502 twice then 200 → retries and succeeds
    - Mock `uploadFn` returning 502 6 times → throws "failed after 5 retries"
    - Verify concurrency: with concurrency=2 and 4 chunks, verify 2 windows of 2
    - Verify onChunkComplete fires for each successful chunk
    - Verify completed Set skips already-done chunks

    Create `src/upload/chunked-upload.ts`:

    ```typescript
    import { createReadStream, statSync } from 'node:fs'
    import { stat } from 'node:fs/promises'
    import * as path from 'node:path'
    import { ChunkedUploadParams, ChunkedUploadResult, ChunkDescriptor, DEFAULT_CHUNK_SIZE, DEFAULT_CONCURRENCY, DEFAULT_MAX_RETRIES } from './types.js'
    import { uploadChunkPool, type ChunkUploadResponse } from './chunk-pool.js'

    export async function uploadChunked(params: ChunkedUploadParams): Promise<ChunkedUploadResult>
    ```

    Implementation details:
    1. Validate file exists using `fs.stat(params.filePath)` — throw `Error(\`File not found: ${params.filePath}\`)` if ENOENT
    2. Get file size from stat result
    3. Compute chunk descriptors: `Math.ceil(totalSize / chunkSize)` chunks, each 1-indexed, with `start = (i) * chunkSize`, `end = Math.min(start + chunkSize, totalSize)`, `size = end - start`
    4. Generate `resumableIdentifier`: `${totalSize}-${path.basename(params.filePath)}-${Date.now()}`
    5. Create `uploadFn(chunk: ChunkDescriptor)` that:
       - Reads the file slice using `createReadStream(filePath, { start: chunk.start, end: chunk.end - 1 })` and collects into a Buffer
       - Builds FormData with all resumable.js fields (upload_token, file as Blob, resumableChunkNumber, resumableChunkSize as the configured chunkSize, resumableTotalSize, resumableIdentifier, resumableFilename, resumableTotalChunks)
       - POSTs to `params.uploadUrl` using native `fetch()` (NOT openapi-fetch — per RESEARCH.md anti-pattern)
       - Returns `{ status: response.status, data: await response.json() }` (wrapped in try/catch for network errors → return status 0 to trigger retry)
    6. Track `bytesUploaded = 0`; in `onChunkComplete` callback, increment by chunk.size and call `params.onProgress?.(bytesUploaded, totalSize)`
    7. Call `uploadChunkPool({ chunks, uploadFn, concurrency, maxRetries, onChunkComplete })`
    8. Return the `finalResponse` from the pool result as `ChunkedUploadResult`

    Write tests in `__tests__/chunked-upload.test.ts`:

    - Mock `fetch` globally, verify FormData fields match resumable.js protocol
    - Verify resumableIdentifier contains file size and filename
    - Verify onProgress fires with cumulative bytes
    - Verify file-not-found throws clear error
    - Verify native fetch is used (not openapi-fetch)

    IMPORTANT: Do NOT import chalk, ora, or cli-progress in this file. The engine is display-agnostic — progress is reported via the onProgress callback.
