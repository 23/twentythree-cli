1. Create `packages/twentythree-cli/src/api/client.ts`:

```typescript
import createClient, { type Middleware } from 'openapi-fetch'
import type { paths } from './types.js'

export interface ClientConfig {
  domain: string
  token?: string  // undefined in domain-only/anonymous mode
}

/**
 * Create a typed openapi-fetch client for a TwentyThree workspace.
 *
 * When token is provided, an auth middleware injects the Authorization header.
 * When token is undefined (domain-only mode per AUTH-11), no auth header is sent.
 */
export function createApiClient(config: ClientConfig) {
  const client = createClient<paths>({
    baseUrl: `https://${config.domain}`,
  })

  if (config.token) {
    const authMiddleware: Middleware = {
      async onRequest({ request }) {
        request.headers.set('Authorization', `Bearer ${config.token}`)
        return request
      },
    }
    client.use(authMiddleware)
  }

  return client
}
```

Note: baseUrl is `https://${domain}` (not `https://${domain}/api/2`) because the OpenAPI paths in types.ts already include the full path structure. Check the generated types to confirm the path format and adjust baseUrl accordingly.

Create `packages/twentythree-cli/src/lib/base-command.ts` with two exported abstract classes:

**BaseCommand** (extends oclif Command):
- `static enableJsonFlag = true` — all commands support --json
- `static baseFlags` with `workspace` flag: `Flags.string({ char: 'w', summary: 'Workspace domain or display name to use for this invocation.', helpGroup: 'GLOBAL' })`
- Protected instance properties:
  - `flags`: typed flags from parse
  - `activeWorkspace`: resolved WorkspaceEntry (or a minimal `{ domain: string; token?: string }` for domain-only mode)
  - `apiClient`: the openapi-fetch client (created from activeWorkspace)
- `init()` method:
  1. Calls `super.init()`
  2. Parses flags via `this.parse()` with baseFlags merge
  3. Resolves workspace: if `--workspace` flag provided, calls `findWorkspace(flag, getWorkspaces())`; otherwise uses `getActiveWorkspace()` + `getWorkspaceForDomain()`
  4. If workspace resolved and has token, calls `ensureFreshToken(domain)` to ensure token is fresh
  5. Creates API client via `createApiClient({ domain, token })`
  6. Stores resolved workspace and client as instance properties
  7. If no workspace configured at all (no active, no --workspace), logs error: "No workspace configured — run `twentythree auth credentials` to set up" and exits 1
  8. If `--workspace` flag matches multiple workspaces, uses `@clack/prompts` select to disambiguate
- `printWorkspaceHeader()` method: logs `chalk.dim('[' + this.activeWorkspace.domain + ']')` — call this at top of every command's `run()` (AUTH-04)

**AuthenticatedCommand** (extends BaseCommand):
- Overrides `init()`: calls `super.init()`, then checks `this.activeWorkspace.token`. If falsy, calls `this.error('This command requires authentication — run \`twentythree auth credentials\` to add a bearer token', { exit: 1 })` (exact AUTH-10 message)

| T-02-08 | Information Disclosure | client.ts auth middleware | mitigate | Authorization header added ONLY when config.token is truthy. In domain-only mode, no middleware registered — no header sent. Prevents token leakage on anonymous-scope endpoints (AUTH-11). |
