**1. Create `packages/twentythree-cli/src/commands/auth/credentials.ts`:**

This command does NOT extend BaseCommand — it uses raw oclif Command because it runs before any workspace is configured.

```typescript
import { Command } from '@oclif/core'
import * as p from '@clack/prompts'
```

Flow:
1. `p.intro('TwentyThree credentials')`
2. Prompt for domain: `p.text({ message: 'Domain (e.g. company.video23.com)', validate: v => v.includes('.') ? undefined : 'Enter a valid domain' })`
3. Check `p.isCancel()` after each prompt — if cancelled, `p.cancel('Cancelled')` and return
4. Prompt for token: `p.text({ message: 'Bearer token (press Enter to skip for anonymous access)', placeholder: 'optional' })`
5. If token provided (non-empty string after trim):
   a. Store login token in keychain: `setCredential(domain, token)` (AUTH-01 — overwrites if exists, per CONTEXT.md re-auth behavior)
   b. Show spinner: `const s = p.spinner(); s.start('Discovering workspaces...')`
   c. Call `fetchWorkspaceTokens(domain, token)` (AUTH-02)
   d. `s.stop('Workspaces discovered')`
   e. If multiple workspaces returned, prompt user to select which to activate (AUTH-03):
      - Use `p.multiselect({ message: 'Select workspaces to activate', options: workspaces.map(w => ({ value: w.domain, label: \`\${w.displayName} (\${w.domain})\` })), required: true })`
      - Filter workspace list to only selected
   f. Prompt to set default: `p.select({ message: 'Default workspace', options: selectedWorkspaces.map(...) })`
   g. Store workspaces via `setWorkspaces(selectedWorkspaces)` and `setActiveWorkspace(defaultDomain)`
6. If token is empty/skipped (domain-only mode):
   a. Do NOT store anything in keychain
   b. Store domain-only entry in conf: `setWorkspaces([{ domain, displayName: domain, token: '', expiresAt: 0 }])` and `setActiveWorkspace(domain)`
   c. Log info about anonymous mode limitations
7. `p.outro('Credentials saved')`

`static description = 'Configure domain and bearer token for a TwentyThree workspace'`
`static examples = ['<%= config.bin %> auth credentials']`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user terminal input -> CLI | Domain and bearer token entered via interactive prompts |
| CLI -> @clack/prompts | User input handled by third-party prompt library |
| CLI -> OS keychain | Bearer token stored via @napi-rs/keyring |
| CLI -> TwentyThree API | Workspace discovery call with login token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Information Disclosure | credentials.ts prompt | mitigate | Token entered via p.text — @clack/prompts does not echo sensitive input differently than regular text. Accept: terminal is user's own machine; no remote exposure. Token is never logged to stdout after entry. |
| T-02-13 | Information Disclosure | credentials.ts | mitigate | Login token stored ONLY in OS keychain via setCredential. Never written to conf, log files, or error messages. Domain-only mode does not call setCredential at all. |
| T-02-14 | Information Disclosure | status.ts | mitigate | auth status NEVER displays the token value. Shows domain, display name, auth mode, and expiry only. Even with --json, token is excluded from output. |
| T-02-15 | Spoofing | use.ts workspace matching | accept | findWorkspace matches against stored workspace list only. User can only switch to workspaces they previously authenticated. No external input creates new workspaces. |
</threat_model>
