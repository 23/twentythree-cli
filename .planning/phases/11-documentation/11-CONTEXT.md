# Phase 11: Documentation - Context

**Gathered:** 2026-04-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Generate and write the `docs/` directory at `packages/twentythree-cli/docs/`. Deliverables are three things:
1. `docs/commands/` — per-topic markdown files generated by `oclif readme --multi --nested-topics-depth 2`, plus a handwritten index
2. `docs/guides/getting-started.md` — auth setup, workspace selection, first command (`video list`)
3. `docs/guides/api-spec-upgrade.md` — standalone contributor guide for updating the OpenAPI spec

Phase 12 owns root README, npm package README, and CHANGELOG. Phase 13 owns publishing.

</domain>

<decisions>
## Implementation Decisions

### docs/ Location (D-01)

- **D-01:** All docs live at `packages/twentythree-cli/docs/`. No symlink, no copy to repo root. Phase 10 already added `/docs` to the package's `files` array — the package directory IS the canonical home. Phase 12's root README links into them via relative paths (e.g., `packages/twentythree-cli/docs/commands/`).

### Command Reference (D-02–D-04)

- **D-02:** Use `oclif readme --multi --nested-topics-depth 2` run from `packages/twentythree-cli/`. Output goes to `packages/twentythree-cli/docs/commands/`.
- **D-03:** Write a handwritten `docs/commands/README.md` index listing all 22 top-level topics with one-line descriptions. This is the entry point for anyone browsing the command reference.
- **D-04:** Depth 2 as specified in requirements — topics like `analytics:video` get their own page grouping all `timeseries`, `totals`, `weekday` etc. commands. No further nesting.

### Getting Started Guide (D-05–D-07)

- **D-05:** The "first command" example is `twentythree video list`. It demonstrates the CLI's core purpose (API access to video content) and is immediately useful.
- **D-06:** Show expected output for each command in the guide — include a sample table so readers know what to expect. Use placeholder/illustrative data (not real workspace data).
- **D-07:** Tone is concise with brief explanations — each step has 1-2 sentences of context (e.g., "This stores your credentials in the OS keychain — you won't be prompted again") followed by the command. Scannable but not dry. Covers exactly what DOCS-02 specifies: auth credentials setup → workspace selection → first command.

### api-spec-upgrade Guide (D-08–D-09)

- **D-08:** Written for contributors who use Claude Code. Full workflow: run `pnpm update-api-spec` → read the diff output → paste into Claude Code session → fix TypeScript errors → run tests → commit. The guide explains what to look for in the diff (new endpoints, removed endpoints, changed params).
- **D-09:** Standalone guide, not a reference to CLAUDE.md. Same workflow as CLAUDE.md but written for human contributors with full prose. CLAUDE.md is terse and agent-optimized; this guide is readable documentation. No cross-linking required.

### Claude's Discretion

- File names and internal heading structure for the guides
- Whether to include a "prerequisites" section at the top of the getting started guide (install step)
- Exact placeholder values used in example output
- Whether to include a "Next steps" footer linking to the command reference

</decisions>
