**Audience:** Contributors who use Claude Code. Not agent-optimized — written as readable human documentation.

**Required sections and content:**

1. **Heading:** `# Updating the API Spec`

2. **Overview** (`## Overview`)
   - 1 paragraph: The TwentyThree API evolves over time. When the upstream OpenAPI spec changes, the CLI's type definitions and affected commands need to be updated. This guide walks through the full update workflow.

3. **Prerequisites** (`## Prerequisites`)
   - pnpm (workspace-level dependency management)
   - Claude Code (for assisted command fixes)
   - The repo cloned and dependencies installed (`pnpm install`)

4. **Step 1: Run the update script** (`## Step 1: Run the update script`)
   - Command from repo root: `pnpm update-api-spec`
   - Or from the CLI package: `cd packages/twentythree-cli && ./update-api-spec.sh`
   - Explain what the script does in 3 bullet points:
     1. Downloads the latest OpenAPI spec to `packages/twentythree-cli/specs/twentythree-api-swagger.json`
     2. Prints a `git diff` of the spec file showing what changed
     3. Runs `pnpm generate-types` to regenerate `src/api/types.ts` from the updated spec

5. **Step 2: Read the diff output** (`## Step 2: Read the diff output`)
   - The script prints a raw `git diff` of the JSON spec file. Explain what to look for:
     - **New `paths` entries** = new API endpoints that may need new CLI commands
     - **Removed `paths` entries** = endpoints that no longer exist; existing commands may break
     - **Changed `parameters` or `requestBody`** under an existing path = TypeScript errors will surface these when you compile
     - **Changed `responses` shapes** = TypeScript errors will surface these too
   - Include a short illustrative diff example showing a new path being added:
     ```diff
     +    "/api/video/analytics/engagement": {
     +      "get": {
     +        "operationId": "getVideoAnalyticsEngagement",
     +        "parameters": [...]
     +      }
     +    },
     ```

6. **Step 3: Fix TypeScript errors with Claude Code** (`## Step 3: Apply changes with Claude Code`)
   - First, capture errors: `pnpm --filter twentythree-cli exec tsc --noEmit`
   - Open a Claude Code session
   - Paste the diff output and any TypeScript errors
   - Ask Claude to update affected command files and fix broken types
   - Note: The codebase may have pre-existing type errors unrelated to the spec change. Focus on errors that are newly introduced.

7. **Step 4: Verify** (`## Step 4: Verify`)
   - Run both: `pnpm --filter twentythree-cli exec tsc --noEmit` and `pnpm --filter twentythree-cli test --run`
   - Both should pass without new errors from the spec update.

8. **Step 5: Commit** (`## Step 5: Commit`)
   - Commit these files together in one commit:
     - `packages/twentythree-cli/specs/twentythree-api-swagger.json` (updated spec)
     - `packages/twentythree-cli/src/api/types.ts` (regenerated types)
     - Any command files updated to match the new spec
   - Example commit message: `chore: update API spec and regenerate types (YYYY-MM-DD)`

**Style rules:**
- ATX headings (`#`, `##`)
- Code blocks use triple backtick fences with `bash` or `diff` language tags
- No emojis
- Standalone guide — do NOT reference or link to CLAUDE.md (per D-09)
- Blank line between every block element
