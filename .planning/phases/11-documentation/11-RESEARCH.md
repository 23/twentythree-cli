## Summary

Phase 11 is primarily an execution phase, not a research phase. All decisions are locked in CONTEXT.md; no technology choices need to be made. The research validates that the locked approach works and provides the exact command invocations, output shapes, and file structures the planner needs to write precise task instructions.

`oclif readme --multi --nested-topics-depth 2` has been verified against the live codebase (244 commands, 24 top-level topics). When invoked from `packages/twentythree-cli/` with `--output-dir docs/commands`, it creates 49 files: one `.md` per top-level topic and one `.md` per sub-topic (depth 2), nested in subdirectories matching the topic hierarchy. The command requires two things to work: a `README.md` at the target `--readme-path` must pre-exist (even if empty), and the output directory does not need to pre-exist (oclif creates it).

The two handwritten guides are straightforward prose authoring tasks. The getting-started guide follows a 3-step sequential flow: `auth credentials` (interactive prompt), automatic workspace discovery, `workspace use` to select active workspace, then `video list` as the first real API call. The api-spec-upgrade guide formalizes the workflow already described in `CLAUDE.md §API Change Workflow` and in `update-api-spec.sh`.

**Primary recommendation:** Run `oclif readme --multi --nested-topics-depth 2` first to generate the command reference, then write the two guides using verified command names and placeholder output.

### Pattern 1: oclif readme Multi-Mode Invocation

**What:** Generates per-topic markdown files from the oclif manifest. Must run from `packages/twentythree-cli/` so oclif can locate the manifest and compiled commands.

**When to use:** Whenever the command set changes or a fresh docs generation is needed.

**Verified behavior:** [VERIFIED: live codebase run 2026-04-16]
- Requires `README.md` to exist at `--readme-path` (even empty file suffices; oclif updates the `<!-- commands -->` block)
- `--output-dir` path is resolved relative to `pluginDir` (which defaults to `process.cwd()`)
- Absolute paths for `--output-dir` do NOT work correctly — oclif resolves relative to pluginDir then uses `path.join('.', outputDir, ...)`. Use a relative path like `docs/commands`.
- With 244 commands and 24 topics at depth 2, generates exactly 49 markdown files
- Links in the README use the `--output-dir` value as-is (e.g., `docs/commands/video.md`)

```bash
# Run from packages/twentythree-cli/
cd packages/twentythree-cli

# README.md must exist (will be updated in-place)
touch README.md  # only if it doesn't exist yet

# Generate command reference docs
node_modules/.bin/oclif readme \
  --multi \
  --nested-topics-depth 2 \
  --output-dir docs/commands \
  --readme-path README.md
```

**Alternative using pnpm filter (from repo root):**
```bash
pnpm --filter twentythree-cli exec oclif readme \
  --multi \
  --nested-topics-depth 2 \
  --output-dir docs/commands \
  --readme-path README.md
```

### Pattern 4: API Spec Upgrade Guide Content

**Verified source material:** [VERIFIED: update-api-spec.sh + CLAUDE.md]

Full workflow to document:
1. Run `pnpm update-api-spec` from repo root (or `./update-api-spec.sh` from `packages/twentythree-cli/`)
2. Script downloads latest spec to `packages/twentythree-cli/specs/twentythree-api-swagger.json`
3. Script prints `git diff` of the spec file — shows new endpoints, removed endpoints, changed params
4. Script runs `pnpm generate-types` to regenerate `src/api/types.ts`
5. Run `pnpm --filter twentythree-cli exec tsc --noEmit` to find TypeScript errors
6. Open Claude Code, paste diff + TypeScript errors
7. Ask Claude to update affected command files and fix broken types
8. Run `pnpm --filter twentythree-cli test --run`
9. Commit: spec file + types file + any updated command files

**What to explain in the diff section:** The diff of `twentythree-api-swagger.json` is a raw JSON diff. Guide readers need to understand:
- New `paths` entries = new API endpoints → may need new commands
- Removed `paths` entries = removed endpoints → existing commands may break
- Changed `parameters` or `requestBody` under an existing path → TypeScript errors will surface these
- Changed `responses` shapes → TypeScript errors will surface these

### Anti-Patterns to Avoid

- **Running oclif readme from the wrong directory:** If run from the repo root rather than `packages/twentythree-cli/`, oclif cannot find the manifest. Always cd into the package first or use `pnpm --filter`.
- **Using absolute paths for `--output-dir`:** oclif resolves `--output-dir` relative to the plugin directory (process.cwd()). Passing `/absolute/path` results in files being written at `<cwd>/<absolute-path>` (doubled path). Use `docs/commands` (relative).
- **Running before the manifest exists:** `oclif.manifest.json` must exist. It is generated by `pnpm build` (via `postbuild: oclif manifest`). It already exists in the repo — do not delete it before running.
- **Committing the README.md `<!-- commands -->` block update as part of Phase 11:** Phase 12 owns the root README and npm README. The `README.md` touched by `oclif readme` here is `packages/twentythree-cli/README.md` — which Phase 12 will write properly. Phase 11 may need to create a stub README.md if Phase 12 hasn't run yet; the plan should not depend on Phase 12's README being final.

## Common Pitfalls

### Pitfall 1: README.md Must Pre-Exist

**What goes wrong:** `oclif readme` errors with `ENOENT: no such file or directory, open '.../README.md'` and exits without writing any output.

**Why it happens:** The command reads the existing README to find `<!-- commands -->` and `<!-- usage -->` marker tags, then replaces them in-place. It does not create the file from scratch.

**How to avoid:** Create `packages/twentythree-cli/README.md` before running the command. A minimal stub with `<!-- usage -->` and `<!-- commands -->` markers is sufficient, or even an empty file. Phase 12 will overwrite the README with final content — the stub is disposable.

**Warning signs:** Command exits immediately with ENOENT error code.

### Pitfall 2: oclif readme Updates the README In-Place

**What goes wrong:** The `<!-- commands -->` block in `README.md` gets replaced with a long auto-generated command listing. If Phase 12 has already written the README, this overwrites it.

**Why it happens:** `oclif readme` writes the command table into the `<!-- commands -->` region of `--readme-path`. It is not a separate operation.

**How to avoid:** Use a dedicated stub `README.md` for the Phase 11 doc generation step, understanding that Phase 12 will write the final README. The command reference docs in `docs/commands/` are the deliverable — the README update is a side effect, not the goal.

**Warning signs:** Phase 12 planner or reviewer finds unexpected content in README.md that was generated rather than authored.

### Pitfall 3: Output Dir Links Use the Flag Value Verbatim

**What goes wrong:** The generated `README.md` `<!-- commands -->` block contains links like `(docs/commands/video.md)` — relative to wherever `README.md` lives. If the README is at the repo root but the docs are in the package subdirectory, the links are broken.

**Why it happens:** oclif uses the `--output-dir` value as-is when constructing Markdown links. It does not relativize based on where the README lives.

**How to avoid:** The README and the docs directory must be co-located or the relative path must be correct. Since both the README and docs live in `packages/twentythree-cli/`, and `--output-dir docs/commands` is relative to that directory, the links will be correct for anyone browsing from the package root.

### Pitfall 4: doctor Is a Command, Not a Topic

**What goes wrong:** `doctor` appears in the topic list with `--nested-topics-depth 2` because oclif treats single-file commands differently from topic-grouped commands.

**Why it happens:** `doctor.ts` is a standalone command at `src/commands/doctor.ts` — it generates `docs/commands/doctor.md`. It is not a topic directory. The handwritten index should list it as `` `twentythree doctor` `` (a command entry, not a topic directory link) so readers don't expect sub-pages.

**Warning signs:** Index links to `doctor/` subdirectory that doesn't exist.
