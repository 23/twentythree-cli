## Warnings

### WR-01: docs/commands/README.md states "24 topics" but there are 25

**File:** `packages/twentythree-cli/docs/commands/README.md:3`
**Issue:** The opening line reads "TwentyThree CLI provides 244 commands across 24 topics." The table in the same file lists 25 topics: action, analytics, app, audience, auth, category, collector, comment, doctor, openupload, player, poll, presentation, protection, session, setting, site, spot, tag, thumbnail, user, video, webhook, webinar, workspace. The manifest confirms 244 commands, so only the topic count is wrong.
**Fix:**
```markdown
TwentyThree CLI provides 244 commands across 25 topics.
```

---

### WR-02: getting-started.md workspace-selection description is misleading

**File:** `packages/twentythree-cli/docs/guides/getting-started.md:27`
**Issue:** The guide says: "the CLI automatically discovers all workspaces associated with your token and **sets the first one as active**. If your token has access to multiple workspaces, you will be prompted to select a default." The two sentences together imply the CLI sets the first workspace active and then additionally prompts when there are multiple. The actual source behavior (in `src/commands/auth/credentials.ts`) is mutually exclusive: if exactly one workspace is returned, it is set active without prompting; if multiple workspaces are returned, the user is prompted to select one and that selection is set active. The phrase "sets the first one as active" is never actually true — it either sets the only one, or it sets whichever one the user selects.
**Fix:**
```markdown
After you enter a bearer token, the CLI discovers all workspaces associated with your
token. If only one workspace is found, it is set as active automatically. If multiple
workspaces are found, you will be prompted to select a default.
```

## Info

### IN-01: docs/commands/README.md player topic description reflects delete subcommand, not the topic

**File:** `packages/twentythree-cli/docs/commands/README.md:17`
**Issue:** The `player` topic description reads "Delete a player from the active workspace" — the description of `player delete`, not the topic as a whole. This occurs because the player topic has no `index.ts` command, so oclif surfaces the first alphabetical subcommand's description (`delete.ts`). The same applies to `app` ("Create a new app integration") and `collector` ("Block a collector from a video or webinar"), both of which have broader topic scope than their generated description implies. This can confuse users scanning the reference for a player listing or embed command.
**Fix:** Add an `src/commands/player/index.ts` (and similarly for `app` and `collector`) with a representative topic-level description such as "Manage players — list, create, update, delete, embed, and more." Alternatively, manually update the descriptions in the docs if auto-generation is not being used.

### IN-02: README.md version string in usage example will drift

**File:** `packages/twentythree-cli/README.md:9`
**Issue:** The usage block hard-codes `node-v22.22.2` in the example output (`twentythree-cli/0.1.0 darwin-arm64 node-v22.22.2`). This is inside an oclif `<!-- usage -->` auto-generated block, but the Node version string will become stale as Node versions advance and as developers on different machines see different output.
**Fix:** If this block is regenerated by `oclif readme`, no action is needed as long as `oclif readme` is run on updates. If it is maintained manually, replace the version-pinned example with a placeholder: `twentythree-cli/0.1.0 darwin-arm64 node-v22.x.x` or omit the node version from the example entirely.
