The 5 correctness rules (in order, with content guidelines):

**Rule CR-1: Object Type Differentiation**
- Explanation: When calling `comment`, `poll`, `spot`, or other multi-object topics, use `--object-type photo` for videos and `--object-type live` for webinars.
- Bash example: Show `twentythree comment list` twice — once with `--object-type photo` for a video ID, once with `--object-type live` for a webinar ID.

**Rule CR-2: No `webinar get` — Use `webinar list --search`**
- Explanation: There is no `webinar get` command. Retrieve a specific webinar by title or filter by ID client-side using `webinar list --search`.
- Bash example: `twentythree webinar list --search "Q2 Town Hall" --json`

**Rule CR-3: Webinar Creation Defaults**
- Explanation: Verify access visibility flags when creating webinars — defaults may not match intent. Use the VERIFIED flag name from Task 1 (the `open_p` equivalent) to set public or private access explicitly.
- Bash example: Show `twentythree webinar create` with `--title` and the verified open/private flag set explicitly. If the flag was not found in Task 1, show the create command without the flag and note: "Run `twentythree webinar create --agent` to check available access flags."

**Rule CR-4: Timezone Handling**
- Explanation: Always specify `--live-date` in ISO 8601 UTC format (ending in `Z`) to avoid timezone ambiguity when scheduling webinars or time-sensitive events.
- Bash example: `twentythree webinar create --title "Launch Event" --live-date "2026-06-01T14:00:00Z" --json`

**Rule CR-5: Admin Link Construction**
- Explanation: The `--json` response after every upload or create includes `data.admin_url` — use that value directly. Never construct admin URLs by concatenating domain + ID.
- Bash example: Show uploading a video with `--json` and then `echo "Admin URL: $(echo $RESPONSE | jq -r '.data.admin_url')"` or a similar two-step that reads `data.admin_url` from the response.

**Section 2: ## Preference Rules**

Open with:

## Preference Rules

Then add exactly 3 rules using the same ### heading + one-line explanation + bash block + --- format:

**Rule PR-1: Thumbnails from Listing Response**
- Explanation: When you need a video's thumbnail URL, prefer `video list --json` — the response includes thumbnail data. Avoid a separate `thumbnail list` call when the listing suffices.
- Bash example: `twentythree video list --limit 10 --json` with a note that `data[].thumbnail_*` fields are included in list output.

**Rule PR-2: Analytics via Listing Flags**
- If `--include-analytics` (or the verified equivalent) WAS FOUND in Task 1 on `video list` or `webinar list`: Write the rule using the verified flag name. Explanation: Include analytics data directly in listing calls using the verified flag rather than making a separate analytics command call. Bash example: `twentythree video list --include-analytics --json` (or the verified flag name).
- If `--include-analytics` was NOT FOUND on either command: Reframe the rule to "Prefer listing endpoints that return richer data to minimize round trips. Combine `--limit`, `--all`, and available filter flags to reduce the number of API calls." Bash example: `twentythree video list --all --json | jq '.data[] | {id, title, status}'`.

**Rule PR-3: Filtering and Sorting on Listing Endpoints**
- Explanation: Apply filtering and sorting via CLI flags on listing commands rather than fetching all results and filtering client-side. Check `--agent` output for available filter flags before writing client-side filtering logic.
- Bash example: Show `twentythree webinar list --status upcoming --limit 10 --json` and `twentythree video list --limit 20 --include-unpublished --json` as two examples.
