### Shell Script Structure

Script path: `packages/twentythree-cli/update-api-spec.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
SPECS_DIR="$SCRIPT_DIR/specs"
SPEC_FILE="$SPECS_DIR/twentythree-api-swagger.json"
SPEC_URL="https://video.twentythree.com/apidocs/swagger.json"

mkdir -p "$SPECS_DIR"

echo "Downloading latest spec from $SPEC_URL..."
curl -fsSL "$SPEC_URL" -o "$SPEC_FILE"

echo ""
echo "--- Spec diff ---"
if git -C "$SCRIPT_DIR" ls-files --error-unmatch "specs/twentythree-api-swagger.json" > /dev/null 2>&1; then
  git -C "$SCRIPT_DIR" diff specs/twentythree-api-swagger.json
else
  echo "(New file — showing full content as diff)"
  git diff --no-index /dev/null "$SPEC_FILE" || true
fi

echo ""
echo "Regenerating types..."
cd "$SCRIPT_DIR" && pnpm exec openapi-typescript specs/twentythree-api-swagger.json -o src/api/types.ts

echo ""
echo "Spec updated. Review the diff above, then follow CLAUDE.md § API Change Workflow."
```

### git diff First-Run Behavior

**Verified** `[VERIFIED: local bash test]`:

| State | `git diff <file>` output | Correct approach |
|-------|--------------------------|-----------------|
| File never committed (untracked) | Empty — produces no output | Use `git diff --no-index /dev/null <file>` |
| File committed, then changed | Full diff output | `git diff <file>` works directly |

Detection method: `git ls-files --error-unmatch <path>` exits 0 if tracked, non-zero if untracked. This is the correct way to branch between first-run and subsequent runs.

Alternative detection: `git status --short <path>` returns `?? <path>` for untracked. Either works; `ls-files --error-unmatch` is more idiomatic.

## Common Pitfalls

### Pitfall 1: Path Resolution in Shell Script
**What goes wrong:** Script uses relative paths that break when invoked from a different cwd (e.g., from monorepo root via the pnpm alias).
**Why it happens:** `./specs/file.json` resolves relative to wherever the shell is, not where the script lives.
**How to avoid:** Use `BASH_SOURCE[0]` to anchor all paths to the script's own directory. Every path in the script prefixes with `$SCRIPT_DIR`.
**Warning signs:** Works when run from `packages/twentythree-cli/` but fails from repo root.

### Pitfall 2: git diff Silent on First Run
**What goes wrong:** Developer runs `update-api-spec.sh` for the first time, sees no diff output, assumes the spec is unchanged or that the script failed silently.
**Why it happens:** `git diff` on an untracked file produces zero output — not an error, just empty. `[VERIFIED: local bash test]`
**How to avoid:** Detect untracked state with `git ls-files --error-unmatch`; fall back to `git diff --no-index /dev/null "$SPEC_FILE"` which shows the entire file as a new-file diff.

### Pitfall 3: curl vs wget Portability
**What goes wrong:** Script uses `wget` which is not installed by default on macOS.
**Why it happens:** wget is a common Linux tool but is not bundled with macOS. curl is bundled.
**How to avoid:** Use `curl -fsSL <url> -o <file>`. The `-f` flag makes curl fail on HTTP errors (4xx/5xx), `-sS` suppresses progress but shows errors, `-L` follows redirects. `[VERIFIED: curl 8.7.1 at /usr/bin/curl]`

### Pitfall 4: set -e Interaction with git diff Exit Code
**What goes wrong:** `git diff` exits with code 1 when there are differences — not an error, just "changes found". With `set -e`, the script aborts when diff finds changes.
**Why it happens:** POSIX diff convention: exit 0 = no differences, exit 1 = differences found, exit 2 = error.
**How to avoid:** Use `git diff <file> || true` to swallow the non-zero exit when differences exist. Similarly for `git diff --no-index`.

### Pitfall 5: Script Not Executable
**What goes wrong:** `./update-api-spec.sh` returns "Permission denied".
**Why it happens:** Git doesn't track file permissions by default across platforms; freshly written shell scripts need `chmod +x`.
**How to avoid:** Set executable bit explicitly: `chmod +x packages/twentythree-cli/update-api-spec.sh`. Also: `git add` will track the executable bit once set.

## Code Examples

### Pattern 1: Detect Untracked vs Tracked File in Bash
```bash
# Source: verified via local bash test
if git -C "$SCRIPT_DIR" ls-files --error-unmatch "specs/twentythree-api-swagger.json" > /dev/null 2>&1; then
  # File is tracked by git — show diff against last commit
  git -C "$SCRIPT_DIR" diff specs/twentythree-api-swagger.json || true
else
  # File not yet in git (first run) — show full content as new-file diff
  git diff --no-index /dev/null "$SPEC_FILE" || true
fi
```
